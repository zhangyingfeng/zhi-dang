# Bug修复记录

本文记录已经确认的问题、根因和修复方式，便于维护者避免回归。

## 1.0.0-preview.6：打包应用下载后提示"已损坏"，无法打开

### 现象

从浏览器正常下载 dmg 安装后，双击应用直接提示"知档.app 已损坏，无法打开。你应该将它移到废纸篓。"，没有任何绕过方式——不是预期中可以在系统设置里手动允许的"无法验证开发者"提示。

### 根因

打包出的 `.app` 整体没有代码签名。Rust 编译器只会给主可执行文件加一个不完整的 linker 级签名（`codesign -dv` 显示 `Sealed Resources=none`），bundle 里的后端 sidecar 二进制和其他资源都没有被签名覆盖。较新版本 macOS 对完全未签名、又带着"从网络下载"隔离标记（`com.apple.quarantine`）的应用会直接判定为已损坏并拒绝打开，不再像早期版本那样退回到可绕过的"未知开发者"提示。

本地直接 `open` 打包出的 `.app` 一直能正常打开，掩盖了这个问题——本地生成的文件不带隔离标记，根本不会触发这条检查路径，只有真正从网上下载才会暴露。

### 修复

在 `tauri.conf.json` 的 `bundle.macOS.signingIdentity` 设为 `"-"`，让 `tauri build` 自动对整个 bundle（包括 sidecar）做 ad-hoc 签名，不需要 Apple 开发者账号。用手动添加 `com.apple.quarantine` 标记模拟真实下载场景验证过，确认恢复成预期的"系统设置 → 隐私与安全性 → 仍要打开"这个可绕过的两步流程。

### 防回归要求

- 每次正式发布前，必须用 `xattr -w com.apple.quarantine "0083;$(date +%s);Safari;" 知档.app` 模拟下载场景手动验证一次；只在本地 `open` 打开验证不会暴露这个问题；
- `codesign --verify --deep --strict` 必须通过，且 `Sealed Resources` 不能是 `none`。

## 1.0.0-preview.6：禁用状态的强调色按钮看起来仍像可以点击

### 现象

"开始导出"这类用强调色（`AccentColor`）填充的主按钮，disabled 时只是把不透明度降到 0.5，高饱和度的蓝色背景半透明后依然很显眼，跟灰色的次要按钮 disabled 后几乎不可见形成鲜明对比，容易让用户误以为还能点。

### 根因

`button[disabled]` 规则只处理了 `opacity`，没有覆盖背景色，导致不同 variant 的按钮 disabled 后视觉一致性缺失。

### 修复

`button[disabled]` 统一改成中性灰色背景，不管原本是主按钮还是次要按钮。

## 1.0.0-preview.5/preview.6：登录窗口标题栏显示系统默认值"Tauri App"

### 现象

内嵌的知乎登录窗口标题栏显示"Tauri App"，跟应用本身没有任何关系。

### 根因

`create_login_window`（以及 `open_login_window` 的兜底分支）从未显式调用 `.title(...)`，Tauri 在没有配置标题时使用内部默认值。这个窗口需要用户输入知乎账号密码，显示一个陌生的技术性默认标题会削弱用户对"这是「知档」应用一部分"的信任。

### 修复

显式设置 `.title("知档 - 登录知乎")`。

## 1.0.0-preview.5：应用图标在 Dock 中显示为直角方块

### 现象

Dock 里应用图标是直角正方形，不是 macOS 标准的圆角造型。

### 根因

生成图标源文件时，背景色贴满整个 1024×1024 画布、没有自己画圆角，是基于"macOS 会自动裁剪出统一圆角蒙版"这个假设——实测这个假设不可靠。

### 修复

直接在 1024×1024 源图里画好圆角（半径 184px，参照 Apple Big Sur 图标模板比例），重新生成整套图标文件，不再依赖系统自动裁剪。

## 1.0.0-preview.5：主窗口内容出现纵向滚动条

### 现象

窗口内容比窗口本身高，出现滚动条；手动拖动窗口边缘调整大小后更容易复现。

### 根因

两个问题叠加：

1. 用 `document.body.scrollHeight` 测量内容高度来动态调整窗口大小，但 `main` 元素的 `margin-top:64px` 因为 CSS margin collapse 穿透了没有 border/padding 的 `body`，没有被 `scrollHeight` 计入，导致算出的目标高度总是偏小；
2. 窗口本身允许用户手动拖拽调整大小；如果拖得比内容矮，跟"窗口大小完全由内容驱动"这个设计前提直接冲突，必然产生滚动条。

### 修复

- 改用最后一个元素（`footer`）的 `getBoundingClientRect().bottom` 测量真实渲染高度，不受 margin collapse 影响；resize 后还会二次检测是否仍有溢出并自动补足，不完全依赖一次性算准；
- 把主窗口设为不可手动调整大小（`resizable:false`）——窗口高度既然完全由内容驱动，允许用户拖拽只会重新引入这个问题。

### 防回归要求

- 不要用 `document.body.scrollHeight` 测量整页高度，除非确认根节点到 `body` 之间没有会发生 margin collapse 的外边距。

## 1.0.0-preview.4/preview.5 之间：强调色按钮上的文字看不清

### 现象

蓝色（`AccentColor`）按钮上的文字是黑色，跟背景对比度很差。

### 根因

`color:AccentColorText` 这个 CSS 系统颜色关键字在当前使用的 WKWebView 版本里没有解析出可读的文字颜色，回退成了黑色而不是预期的白色。

### 修复

不依赖 `AccentColorText`，直接写死 `color:#fff`。

## 0.3.3：残留Chrome进程导致登录窗口无法再次打开

### 现象

```text
无法打开登录窗口：browserType.launchPersistentContext: Target page, context or browser has been closed
```

Chrome启动日志中可见"正在现有的浏览器会话中打开。"

### 根因

服务被强制终止（例如直接`kill`进程，而不是通过`/api/close`）时，Playwright启动的独立Chrome进程不会跟着一起退出，成为孤儿进程，继续占用`.data/browser-profile`。下次启动服务后再次点击登录，新Chrome进程发现Profile已被占用，转发给旧进程后立即退出，导致Playwright连接失败。

### 修复

- 监听`SIGINT`和`SIGTERM`，收到后先调用`client.close()`优雅关闭浏览器，再退出进程。

### 防回归要求

- 正常方式（Ctrl+C、非`-9`的`kill`）停止服务时，浏览器进程必须一并退出；
- 不得假设进程被终止后浏览器会自动清理；`kill -9`强杀属于已知例外，任何架构都无法覆盖。

## 0.3.3：登录浏览器提示不受支持的命令行标记

### 现象

Chrome信息栏提示"您使用的是不受支持的命令行标记：--no-sandbox。稳定性和安全性会有所下降。"

### 根因

Playwright的`chromiumSandbox`选项默认值是`false`，因此每次启动都会自动加上`--no-sandbox`，与是否root或使用的平台无关；项目代码此前没有显式设置这个选项。

### 修复

- 在`launchPersistentContext`中显式设置`chromiumSandbox:true`，恢复Chromium的沙盒隔离。

### 防回归要求

- 修改浏览器启动参数时，需要确认沙盒仍然开启（启动命令中不应包含`--no-sandbox`）。

## 0.3.1：浏览器关闭后无法再次登录

### 现象

点击“打开登录窗口”后出现：

```text
无法打开登录窗口：page.goto: Target page, context or browser has been closed
```

### 根因

独立Chrome窗口被关闭后，服务器仍保留旧的Playwright `BrowserContext`和`Page`引用。再次登录时，旧代码只检查上下文变量是否存在，没有确认页面和浏览器是否仍然有效。

测试过程中还发现，4317端口上的旧服务器进程会继续提供旧版代码，使已经修复的源码看起来仍然报同样错误。

### 修复

- 监听页面和浏览器上下文关闭；
- 自动清除失效引用；
- 页面关闭但上下文有效时创建新页面；
- 导航遇到目标已关闭时重建上下文并重试一次；
- 关闭失效上下文时忽略“已经关闭”的清理错误；
- 文档增加端口、旧进程和旧构建检查方法。

### 防回归要求

- 不得假定非空对象就是有效浏览器对象；
- `/api/status`不得为了检测登录状态反复创建或访问页面；
- 修改浏览器生命周期后要测试“打开、手动关闭、重新打开、服务端关闭”四种路径。

## 0.3.1：120条被误判为只取得119条

### 现象

```text
知乎返回总数120，实际取得119，为避免生成不完整归档已停止。
```

### 根因

旧代码把接口报告的原始分页总数与去重后的唯一内容数量直接比较。分页边界、置顶内容或接口行为可能让同一个ID出现两次。例如接口实际返回120条记录，其中一条重复，正确结果应是119篇唯一内容，而不是漏掉一篇。

### 修复

分页报告现在分别保存：

```json
{
  "reportedTotal": 120,
  "received": 120,
  "unique": 119,
  "duplicates": 1,
  "warning": null
}
```

- `reportedTotal`：接口声称的记录数；
- `received`：所有分页原始返回记录数；
- `unique`：按内容类型和ID去重后的数量；
- `duplicates`：重复记录数；
- `warning`：原始返回数与接口总数不一致时的警告。

只有`received`与`reportedTotal`不一致才产生完整性警告。工具仍导出能够取得的内容，并把警告写入`export-report.json`，不再因为可解释的重复记录而停止。

### 防回归要求

- 完整性检查必须发生在去重前；
- 去重不能静默进行，必须报告重复数量；
- 不得把接口总数、原始记录数和唯一内容数混成一个字段。

## 0.3.0：状态轮询产生高频外部请求

### 现象

页面只是保持打开，也会频繁请求账号接口，增加限流和安全验证概率。

### 根因

前端每1.2秒调用本地`/api/status`，旧服务器每次收到状态请求又调用一次第三方`/api/v4/me`。

### 修复

登录状态保存在本地进程内存。`/api/status`只返回本地状态，只有用户确认登录和开始导出时才检查实际账号会话。

## 0.3.0：图片重复

### 现象

Markdown或网站中同一张正文图片连续出现两次。

### 根因

懒加载页面可能同时包含正常`img`节点和`noscript`备用图片；二者转换成Markdown后成为两张相同图片。

### 修复

- 优先使用`data-original`和`data-actualsrc`；
- 删除`noscript`备用块；
- 按图片内容SHA-256命名和去重；
- 增加重复懒加载图片测试。

## 0.3.0：图片失败被静默忽略

### 现象

图片没有下载到本地，但导出过程仍显示成功，之后使用归档时才发现缺图。

### 根因

旧代码使用空的`catch {}`吞掉所有图片下载异常。

### 修复

- 每张图片最多尝试三次；
- 下载失败时保留远程地址；
- 把内容ID、图片地址和错误写入`export-report.json`；
- 不再把部分成功伪装成完整成功。

## 0.3.0：没有封面、问题ID和收藏数

### 现象

网站无法可靠显示封面，回答无法直接取得问题ID，收藏排序没有数据。

### 根因

初始导出格式没有请求或保存这些字段。

### 修复

- 回答保存独立`questionId`；
- 请求可用的`image_url`或`thumbnail`；
- 没有封面字段时使用正文第一张有效图片；
- 请求可用的收藏字段；接口不提供时保存`null`，不伪造为零。

## 0.3.0：可能覆盖已有归档

### 现象

用户选择已有目录时，索引、报告或同名文件可能被覆盖。

### 根因

初始版本直接在用户输入路径中创建和写入文件，没有验证目录是否为空或是否属于受保护位置。

### 修复

- 只允许不存在或为空的导出目录；
- 拒绝磁盘根目录、用户主目录、项目根目录和内部数据目录；
- 完整导出与未来的增量更新明确分离。

## 0.2.0：登录页或安全验证页被当作JSON

### 现象

登录失效或触发安全验证后出现不清楚的JSON解析错误。

### 根因

旧实现假定成功响应一定是内容JSON，没有先检查HTTP状态、Content-Type和HTML响应。

### 修复

- 检查401、403和其他HTTP状态；
- 检查`Content-Type`；
- 检测HTML登录或安全验证页面；
- 返回明确提示，让用户在正常Chrome窗口中完成验证；
- 不绕过验证。

## 历史日志中的无关页面错误

早期页面环境中出现过第三方监控脚本或页面`fetch`失败。这类错误不一定意味着文章下载失败。当前内容请求通过Playwright浏览器上下文直接发出，不依赖知乎页面中的脚本环境；只有内容接口、图片请求或导出报告明确记录的失败才计入归档失败。
