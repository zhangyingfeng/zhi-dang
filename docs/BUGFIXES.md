# Bug修复记录

本文记录已经确认的问题、根因和修复方式，便于维护者避免回归。

## 0.3.1：浏览器关闭后无法再次登录

### 现象

点击“打开登录窗口”后出现：

```text
无法打开登录窗口：page.goto: Target page, context or browser has been closed
```

### 根因

独立Chrome窗口被关闭后，服务器仍保留旧的Playwright `BrowserContext`和`Page`引用。再次登录时，旧代码只检查上下文变量是否存在，没有确认页面和浏览器是否仍然有效。

测试过程中还发现，4317端口上的旧服务器进程会继续提供旧版代码，使已经修复的源码看起来仍然报同样错误。

### 修复

- 监听页面和浏览器上下文关闭；
- 自动清除失效引用；
- 页面关闭但上下文有效时创建新页面；
- 导航遇到目标已关闭时重建上下文并重试一次；
- 关闭失效上下文时忽略“已经关闭”的清理错误；
- 文档增加端口、旧进程和旧构建检查方法。

### 防回归要求

- 不得假定非空对象就是有效浏览器对象；
- `/api/status`不得为了检测登录状态反复创建或访问页面；
- 修改浏览器生命周期后要测试“打开、手动关闭、重新打开、服务端关闭”四种路径。

## 0.3.1：120条被误判为只取得119条

### 现象

```text
知乎返回总数120，实际取得119，为避免生成不完整归档已停止。
```

### 根因

旧代码把接口报告的原始分页总数与去重后的唯一内容数量直接比较。分页边界、置顶内容或接口行为可能让同一个ID出现两次。例如接口实际返回120条记录，其中一条重复，正确结果应是119篇唯一内容，而不是漏掉一篇。

### 修复

分页报告现在分别保存：

```json
{
  "reportedTotal": 120,
  "received": 120,
  "unique": 119,
  "duplicates": 1,
  "warning": null
}
```

- `reportedTotal`：接口声称的记录数；
- `received`：所有分页原始返回记录数；
- `unique`：按内容类型和ID去重后的数量；
- `duplicates`：重复记录数；
- `warning`：原始返回数与接口总数不一致时的警告。

只有`received`与`reportedTotal`不一致才产生完整性警告。工具仍导出能够取得的内容，并把警告写入`export-report.json`，不再因为可解释的重复记录而停止。

### 防回归要求

- 完整性检查必须发生在去重前；
- 去重不能静默进行，必须报告重复数量；
- 不得把接口总数、原始记录数和唯一内容数混成一个字段。

## 0.3.0：状态轮询产生高频外部请求

### 现象

页面只是保持打开，也会频繁请求账号接口，增加限流和安全验证概率。

### 根因

前端每1.2秒调用本地`/api/status`，旧服务器每次收到状态请求又调用一次第三方`/api/v4/me`。

### 修复

登录状态保存在本地进程内存。`/api/status`只返回本地状态，只有用户确认登录和开始导出时才检查实际账号会话。

## 0.3.0：图片重复

### 现象

Markdown或网站中同一张正文图片连续出现两次。

### 根因

懒加载页面可能同时包含正常`img`节点和`noscript`备用图片；二者转换成Markdown后成为两张相同图片。

### 修复

- 优先使用`data-original`和`data-actualsrc`；
- 删除`noscript`备用块；
- 按图片内容SHA-256命名和去重；
- 增加重复懒加载图片测试。

## 0.3.0：图片失败被静默忽略

### 现象

图片没有下载到本地，但导出过程仍显示成功，之后建站时才发现缺图。

### 根因

旧代码使用空的`catch {}`吞掉所有图片下载异常。

### 修复

- 每张图片最多尝试三次；
- 下载失败时保留远程地址；
- 把内容ID、图片地址和错误写入`export-report.json`；
- 不再把部分成功伪装成完整成功。

## 0.3.0：没有封面、问题ID和收藏数

### 现象

网站无法可靠显示封面，回答无法直接取得问题ID，收藏排序没有数据。

### 根因

初始导出格式没有请求或保存这些字段。

### 修复

- 回答保存独立`questionId`；
- 请求可用的`image_url`或`thumbnail`；
- 没有封面字段时使用正文第一张有效图片；
- 请求可用的收藏字段；接口不提供时保存`null`，不伪造为零。

## 0.3.0：可能覆盖已有归档

### 现象

用户选择已有目录时，索引、报告或同名文件可能被覆盖。

### 根因

初始版本直接在用户输入路径中创建和写入文件，没有验证目录是否为空或是否属于受保护位置。

### 修复

- 只允许不存在或为空的导出目录；
- 拒绝磁盘根目录、用户主目录、项目根目录和内部数据目录；
- 完整导出与未来的增量更新明确分离。

## 0.2.0：登录页或安全验证页被当作JSON

### 现象

登录失效或触发安全验证后出现不清楚的JSON解析错误。

### 根因

旧实现假定成功响应一定是内容JSON，没有先检查HTTP状态、Content-Type和HTML响应。

### 修复

- 检查401、403和其他HTTP状态；
- 检查`Content-Type`；
- 检测HTML登录或安全验证页面；
- 返回明确提示，让用户在正常Chrome窗口中完成验证；
- 不绕过验证。

## 历史日志中的无关页面错误

早期页面环境中出现过第三方监控脚本或页面`fetch`失败。这类错误不一定意味着文章下载失败。当前内容请求通过Playwright浏览器上下文直接发出，不依赖知乎页面中的脚本环境；只有内容接口、图片请求或导出报告明确记录的失败才计入归档失败。
