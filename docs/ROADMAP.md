# Roadmap

本路线图记录「知档」的近期和中期开发方向。它用于帮助维护者控制范围和确定优先级，不代表功能已经完成，也不构成发布时间承诺。

## 当前原则

「知档」只解决一个问题：**完整、安全、可靠地导出作者自己的知乎回答和文章，并保存为开放、可验证、可长期使用的本地归档。**

本路线图只包含把归档这一层做稳所需的工作。

## 阶段 1：稳定 Archive Core

**状态：当前优先级**

目标是把知乎内容导出能力做成可以长期维护和反复验证的核心。

### 可靠性

- 正确处理回答和文章的分页；
- 区分接口报告总数、分页实际返回数和去重后的唯一内容数；
- 对重复记录进行去重并明确报告；
- 对无法解释的数量差异给出完整性警告；
- 在接口结构发生变化时明确停止或降级，而不是静默生成错误数据；
- 对单篇内容和图片失败进行可追踪报告；
- 避免已有归档被意外覆盖。

### 数据完整性

持续完善并稳定以下归档内容：

- Markdown 正文；
- `index.json`；
- `export-report.json`；
- 原文链接；
- 创建和更新时间；
- 问题 ID；
- 点赞、评论和可用的收藏数据；
- 封面；
- 本地化图片。

`index.json` 和 Markdown 应被视为长期数据格式。破坏兼容性的修改必须经过明确的 schema 版本设计。

### 登录与第三方变化

- 正确处理浏览器被关闭、登录失效和重新登录；
- 对知乎正常安全验证给出明确提示；
- 不实现 [ACCEPTABLE_USE.md](ACCEPTABLE_USE.md) 排除的能力（验证码绕过、访问控制规避、代理池、账号池、限流规避）；
- 减少无必要的第三方请求；
- 对接口字段变化保留可测试、可维护的降级路径。

### 隐私与安全

标准见 [PRIVACY.md](PRIVACY.md)、[SECURITY.md](SECURITY.md) 和 [AGENTS.md](../AGENTS.md)；这些是所有阶段都必须保持的底线，不在此重复列出。

### 验证标准

核心导出进入稳定状态前，应逐步做到：

1. 自动测试覆盖关键分页、去重、图片和目录安全场景；
2. `npm test` 和 `npm run build` 持续通过；
3. 在干净环境中验证完整导出；
4. 对已知失败模式有明确的错误信息和故障排查文档；
5. 导出报告能够区分完整成功、可解释重复、部分失败和完整性风险。

## 阶段 2：降低安装和使用门槛

**状态：已完成，1.0.0 已发布**

0.3.x 版本需要用户准备 Node.js、npm、Git 和 Chrome。`v1-tauri` 分支已经把应用重写为基于 [Tauri](https://tauri.app) 的独立桌面应用：知乎登录改为内嵌窗口完成，后端用 [Bun](https://bun.sh) 编译成独立可执行文件随应用打包，普通用户不再需要安装 Node.js、Chrome 或运行任何命令。目标用户流程已经落地：

```text
下载应用
→ 打开应用
→ 点击开始登录
→ 确认保存位置
→ 开始导出
```

这一阶段的硬要求（Archive Core 标准不降低、登录仍在本机完成、不引入云端账号或遥测）都已达成，唯一的已知缺口是平台覆盖——目前只在 macOS（Apple Silicon）上做过完整测试，1.0.0 以 macOS-only 发布。逐条验收过程见 [CHANGELOG.md](CHANGELOG.md)（preview.1 至 1.0.0）。`v1-tauri` 已合并到 `main`，[1.0.0 已正式发布](https://github.com/zhangyingfeng/zhi-dang/releases)。

## 阶段 3：跨平台分发与导出体验重构

**状态：1.1 已正式发布，1.2 尚未开始**

两条互不阻塞的独立轨道，只共享"1.1 功能冻结"这一个前置节点：

| 版本 | 内容 | 状态 |
|---|---|---|
| 1.1 | 导出体验重构：list-first 流程、精确内容哈希检测重复并在列表里只读标出（不做自动判断）、per-item 子任务状态、暂停/继续导出、单项跳过（也是解决"疑似重复"提示的方式——跳过其中一份）、断点续传（重新指向同一目录会复用已完成的部分，不重新下载）。按展示→管理→完善分三个 preview 交付（参考 1.0.0 的节奏）| **已正式发布**——[`1.1.0`](https://github.com/zhangyingfeng/zhi-dang/releases/tag/v1.1.0)（preview.1–3 是构建过程，见 CHANGELOG.md） |
| 1.2 | Apple Developer ID 签名 + 公证，官网直接分发消除 Gatekeeper 警告（目前用免费 ad-hoc 签名，警告可在系统设置里手动绕过，不阻塞使用但不够顺滑） | 未开始，需要 Apple Developer Program 账号 |
| 1.3 | 尝试提交 Mac App Store（需要 App Sandbox 改造和 entitlements）。这一步风险较高——内嵌 WebView 抓取第三方平台数据的工具历史上审核并不宽松，按"低成本尝试，被拒不回炉重做"对待，不影响官网分发作为主渠道 | 未开始，依赖 1.2 |
| 1.4 | Windows 打包与分发：WebView2 登录/会话验证、安装包、代码签名消除 SmartScreen 警告 | 未开始，不依赖 1.3 结果 |
| 2.0 | macOS + Windows 双平台稳定，Archive Core 功能面定型 | 未开始，依赖 1.2–1.4 |

Intel Mac / Linux 不在计划内，仅 macOS（Apple Silicon）+ Windows 两个目标平台。
